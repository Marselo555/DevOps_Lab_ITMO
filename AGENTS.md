# Правила проекта DevOps

- Первоисточник требований: `DevOps-лабы-2-курс (2).docx`; лекции из `drive-download-20261109T224043Z-1-001.zip` — вспомогательный материал. Выполнять только обычные лабораторные 0–3; звёздочки, альтернативные кейсы и отдельные облачные лабораторные исключены.
- Начинать **только ту лабораторную, которую пользователь отдельно запросил**. Не переходить к следующей самостоятельно. Лаборатории 0, 1 и 2 реализованы и проверены локально; лабораторию 3 ждать отдельного запроса. Репозиторий: `https://github.com/Marselo555/DevOps_Lab_ITMO`.
- Один репозиторий и один код блокнота: лабораторная 0 использует `backend/` и `frontend/`; лабораторная 1 хранит свои файлы в `lab1-nginx/`, лабораторная 2 — в `lab2-docker/`, будущая лабораторная 3 — в `.github/workflows/`. Будущие папки не создавать заранее и не дублировать приложение. Сохранять запуск и проверки предыдущих лабораторных.
- Во всех лабораторных одно минимальное приложение-блокнот: CRUD заметок с полями `id`, `title`, `content`. Стек: Python/Flask, HTML/CSS/Vanilla JavaScript, PostgreSQL, Nginx, Docker/Compose, GitHub Actions, Trivy. Не добавлять React, Vue, Kubernetes, Terraform, микросервисы и необязательные технологии.
- Выполнять все обязательные пункты текущей лабораторной без необязательных расширений. Писать минимальный понятный код; не добавлять лишние библиотеки, тесты, сервисы и настройки. Рабочие части предыдущих лабораторных менять только при необходимости.
- Проверять результат реальными запусками и командами. Не выдумывать результаты, метрики, логи, ссылки CI/CD, скриншоты и личные впечатления; не объявлять пункт выполненным без проверки.
- Отчёт создавать только для текущей лабораторной: `reports/lab0.md`, `reports/lab1.md`, `reports/lab2.md` или `reports/lab3.md`. В нём нужны фактические команды, выводы, скриншоты и объяснения; требования к содержимому брать из DOCX.
- Не удалять данные, Docker-тома и чужие контейнеры. Не сохранять реальные секреты или пароли в Git. Не отправлять изменения в удалённый репозиторий без явного разрешения пользователя. Ручные действия описывать конкретно.
- Хост: macOS 26.4.1, `arm64` (проверено `uname -m`). Git 2.50.1, Python 3.9.6, Docker Desktop/Engine 29.9.3 и Compose 5.7.0 доступны; PostgreSQL 16.13 установлен. Nginx и Trivy отсутствуют; Flask и драйвер PostgreSQL установлены в `.venv`, а не в системный `python3`. В корне есть Git-репозиторий на ветке `main` с `origin` на приватный репозиторий пользователя.
- Учитывать macOS и Docker Desktop: не применять к хосту команды только для Windows/Linux. CI может работать на GitHub-hosted Ubuntu, локальный deploy — на этом Mac; настройку локального GitHub Actions runner проверять в лабе 3.
- Лабораторная 1: Nginx в контейнере `devops-lab1-nginx` с конфигурацией `lab1-nginx/nginx.conf`; два Flask-процесса запускаются `lab1-nginx/start-backends.sh`, проверяются `lab1-nginx/check.sh`. Локальные `.env`, `lab1-nginx/.htpasswd`, `lab1-nginx/certs/` и `lab1-nginx/run/` не добавлять в Git. Реальные снимки страницы, `nginx -t` и `check.sh` приложены к `reports/lab1.md`.
- Лабораторная 2: Compose-файл `lab2-docker/compose.yaml` создаёт ровно три сервиса `frontend`, `backend`, `db`; локальный адрес `http://127.0.0.1:8082/`. Данные БД в именованном томе `devops-lab2_notes_data`; не удалять его. Пароль берётся из локального `.env`. Для проверки использованы два Dockerfile, результаты и реальные скриншоты находятся в `reports/lab2.md` и `reports/screenshots/`.
